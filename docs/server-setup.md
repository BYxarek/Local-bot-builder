# Подготовка пользовательского сервера

> Серверный режим находится в разработке. Эта инструкция фиксирует целевую схему развёртывания; текущий прототип запускает `NativeBot.Agent` локально.

## Что потребуется

- сервер с постоянным публичным IP-адресом;
- домен или поддомен, например `bots.example.com`;
- Linux-сервер с доступом по SSH;
- открытые входящие порты `80` и `443`;
- действующий HTTPS-сертификат;
- установленный `NativeBot.Agent` как системная служба.

## DNS

Создайте у DNS-провайдера запись типа `A`, направленную на IPv4-адрес сервера. Если сервер использует IPv6, дополнительно создайте запись `AAAA`.

Проверить разрешение имени можно командой:

```powershell
Resolve-DnsName bots.example.com
```

## HTTPS и reverse proxy

На сервере нужен reverse proxy, например Caddy или Nginx. Он должен:

1. принимать HTTPS-запросы для выбранного домена;
2. автоматически получать или обновлять сертификат;
3. передавать `/webhook/*` на локальный порт `NativeBot.Agent`;
4. не публиковать внутренний порт Agent напрямую в интернет.

Целевая схема:

```text
Интернет :443
  → Caddy или Nginx
  → http://127.0.0.1:8443
  → NativeBot.Agent
```

## Настройки в приложении

После реализации серверного режима приложение будет запрашивать:

- публичный адрес сервера: `https://bots.example.com`;
- SSH-хост и порт для установки и обновлений;
- SSH-пользователя;
- приватный SSH-ключ вместо постоянного пароля;
- ключ доступа к API `NativeBot.Agent`.

Приватные ключи и API-ключи должны храниться в защищённом хранилище Windows и не должны попадать в журналы.

## Проверка готовности

После запуска Agent адрес здоровья должен отвечать через HTTPS:

```powershell
Invoke-WebRequest https://bots.example.com/health
```

Ожидаемый HTTP-статус — `200`. После этого можно переходить к [настройке webhook](webhook-setup.md).
