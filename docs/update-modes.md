# Webhook или long polling

Способ получения событий задаётся отдельно для каждого бота при добавлении и меняется на вкладке «Настройки». После сохранения работающий бот перезапускается в выбранном режиме. В обоих режимах update сначала записывается в устойчивую SQLite-очередь и дедуплицируется по `update_id`.

## Выберите webhooks, если

- продакшн с высокой нагрузкой (>500 событий/день);
- нужна минимальная латентность;
- есть домен и SSL-сертификат;
- масштабируемость критична;
- платформа рекомендует webhooks.

Webhook требует публичного HTTPS-адреса. Для каждого бота Agent создаёт отдельный секрет, регистрирует `allowed_updates` опубликованных сценариев и проверяет заголовок Telegram.

## Выберите long polling, если

- это разработка или тестирование;
- нет доступа к домену или SSL;
- нагрузка ниже 500 событий в день;
- работает один бот без масштабирования;
- это internal-бот без входящего доступа из интернета.

При запуске Agent удаляет прежний webhook и вызывает `getUpdates` с таймаутом 30 секунд. Исходящий доступ к Telegram всё равно необходим.

## Экспорт и импорт

Кнопки находятся в настройках бота. Файл `.nativebot` содержит manifest, черновики и опубликованные версии сценариев, безопасные настройки и ссылки на вложения. Токен, webhook-секрет и Secret variables не экспортируются.
