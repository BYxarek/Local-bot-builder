# Настройка Telegram webhook

Webhook должен вести на собственный HTTPS-домен пользователя. Cloudflare Tunnel, ngrok и локальный сертификат для постоянной работы не требуются.

## Публичный адрес

Для каждого бота используется отдельный маршрут:

```text
https://bots.example.com/webhook/{botId}
```

Базовый адрес `https://bots.example.com` задаётся в приложении. `NativeBot.Agent` добавляет идентификатор бота и регистрирует итоговый адрес через Telegram `setWebhook`.

## Требования

- только HTTPS с действующим публично доверенным сертификатом;
- стабильный домен;
- доступность порта `443` из интернета;
- проверка заголовка `X-Telegram-Bot-Api-Secret-Token`;
- быстрое сохранение Update в устойчивую очередь до отправки успешного ответа;
- дедупликация по `update_id`.

Секрет webhook создаётся отдельно для каждого бота. Его нельзя выводить в интерфейс, журналы или диагностические сообщения.

## Проверка маршрута

Сначала проверьте доступность Agent:

```powershell
Invoke-WebRequest https://bots.example.com/health
```

Сам маршрут webhook не предназначен для проверки обычным GET-запросом. Его вызывает Telegram методом POST после успешной регистрации webhook.

Если обновления не поступают, проверьте DNS, сертификат, reverse proxy, состояние службы `NativeBot.Agent` и сведения Telegram о текущем webhook.
